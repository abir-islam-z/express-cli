Examples & troubleshooting

Common workflows and fixes when something does not work as expected.

Blog API

exm-cli new blog-api --yes --mongo
cd blog-api
exm-cli g module user
exm-cli g module post
exm-cli g module comment
npm install && npm run dev

E-commerce API

exm-cli new shop-api --yes --mongo --module product
cd shop-api
exm-cli g module category
exm-cli g module order
exm-cli g module cart

Supabase + Prisma

exm-cli new api --yes --orm prisma --database postgres --postgres supabase
cd api
# Fill DATABASE_URL and DIRECT_URL in .env from Supabase dashboard
npm install
npx prisma migrate dev

Enable the Supabase MCP server in Cursor when .cursor/mcp.json is present, then complete OAuth in the browser.

Best practices

  • Create the project before running g commands from that directory.
  • Prefer g module over generating six files by hand.
  • Use singular module names (user, not users) for consistent class names.
  • Use --dry-run in scripts and agents before writing files.

Troubleshooting

Command not found

npm list -g express-modular-cli
npm install -g express-modular-cli

Not in a valid Express project

Run generators from the project root that contains src/app/modules. Create one with exm-cli new first.

Component already exists

Pick a new name or remove the existing files under src/app/modules/<name>.

npm install fails offline

Use --no-install when creating the project, then install when you have network access.

Permission errors (global install)

npm config set prefix ~/.local
# ensure ~/.local/bin is on your PATH
