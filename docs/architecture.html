Architecture

How generated projects are organized and how the CLI keeps imports consistent with Node’s ESM rules.

Prisma adds prisma/schema.prisma and src/app/db/. Drizzle adds drizzle.config.ts and schema stubs.

Path aliases (#app)

Node does not read tsconfig paths. Cross-folder imports use package.json imports:

{
  "imports": {
    "#app/*": "./src/app/*.ts"
  }
}
import catchAsync from '#app/utils/catchAsync';
import type { TUser } from './user.interface.ts';
import { UserService } from './user.service.ts';
  • Alias imports omit .ts (the map adds it).
  • Same-folder imports stay relative and include .ts.
  • Type-only imports use import type (Node ESM + verbatimModuleSyntax).

Route registration

src/app/routes/index.ts aggregates module routers:

import { UserRoutes } from '#app/modules/user/user.route';

const moduleRoutes = [
  { path: '/user', route: UserRoutes },
];

moduleRoutes.forEach(route => {
  router.use(route.path, route.route);
});

g module splices imports and entries into this file automatically.

TypeScript on Node

Generated apps use noEmit and run source directly:

npm run dev    # node --watch src/server.ts
npm run start  # node src/server.ts
npm run typecheck

Project validation

Generators require src/app, src/app/modules, and src/app/routes. Otherwise you see an error suggesting exm-cli new first.
